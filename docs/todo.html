Member FFlLinkHandler::findFreeNodeAtPoint (const FaVec3 &point, double tol, int dofFilter=-1) const
This method does not work well with large tolerances. The tolerance is used as a "all within is coincident". In that regime it actually is ID-dependent which node is returned. It is supposed to prioritize the nodes like this:
  1. Replacement node for a WAVGM reference node
  2. WAVGM reference node
  3. Closest free node But if a free node is found that happens to be closer than a found reference node, the free node will be returned instead. There should be two tolerances in this method: Coincident tolerance and search tolerance. JJS 2009.03.27
